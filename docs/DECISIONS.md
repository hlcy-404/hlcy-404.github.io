# 决策记录

## ADR-012 · 服务端部署跟踪与独立发布记录

日期：2026-10-27。将浏览器触发的部署轮询改为服务端调度，复用 `.local/studio/jobs/` 持久化任务。独立探测模块读取指定提交的 Pages 工作流、构建/部署作业和公开版本；调度模块负责去重、网络退避、限流等待、重启恢复与终态。浏览器只刷新本机任务数据，手动检查也进入同一调度入口。

不自动重推 Git 或重跑远端 Actions。停止本地服务期间不查询，恢复副本不启动历史任务。备份时等待进行中的跟踪检查结束，避免复制过程中任务记录变化。界面按任务阶段提供对应操作，技术明细放入可展开区域；常规维护使用卡片分组，范围说明留在指南。

接口依据：[GitHub workflow runs](https://docs.github.com/en/rest/actions/workflow-runs)、[workflow jobs](https://docs.github.com/en/rest/actions/workflow-jobs)，2026-10-27 查阅。按项目固定的 `build` / `deploy` 作业识别失败位置；未知作业失败明确显示工作流失败，不猜测阶段。

## ADR-011 · 可迁移备份、有限清理与源码公开

日期：2026-10-27。用户更新决定：本机编辑器源码可以上传公开仓库，私人数据仍留本机。ADR-010 的源码排除与同步拦截撤销；服务访问限制和站点构建排除继续有效。

采用 fflate 0.8.3（MIT）生成标准 ZIP，marked 18.1.2（MIT）识别文章资源，精确锁定依赖。备份校验逐文件 SHA-256，限制文件数、解压大小及安全路径，拒绝链接和重复路径。完整环境恢复为新目录，原项目不动；保留发布记录但禁止沿用旧发布确认。运行时和安装依赖由锁定版本重新准备，不把数百 MiB 的可重建预览放入备份。

清理范围只包含用户选择的旧预览，保护最近成功预览和用户保留项。先生成确认清单，执行前再核对文件与状态；不自动清理历史、原图或备份。完整 ZIP 和文章 ZIP 均不自动上传，只有源代码及用户确认的正式内容进入 Git。

## ADR-010 · 本地编辑器源码不公开分发（已由 ADR-011 替代）

日期：2026-10-27。用户要求本地编辑器不上传 GitHub。采用精确 Git 忽略规则保留本机源码及启动器，同时在同步脚本中检查已跟踪文件和待推送历史，避免强制加入后被全项目同步带上。博客普通预览和同步工具继续保留，不整体忽略 `tools/`。

源码可见性、服务访问范围、网站产物是三个独立边界：服务继续只监听回环地址并校验请求来源与会话；Jekyll 排除工具目录；Git 忽略规则控制本地源码的默认上传范围。GitHub Pages 托管静态结果，不会运行本机 Node.js 编辑服务。

代价：公开仓库无法重建作者的本地工具，不能再将“同步博客”等同于“备份整个写作环境”。独立备份与可迁移安装包列为优先待办。本轮不创建私有远端、不上传工具、不删除任何本地草稿；手工 Git 命令可绕过快捷脚本，未来改为独立目录/私有版本管理能进一步减少混入机会。

## ADR-009 · 本地版本恢复与固定快照预览

2026-10-27 用户确认实施恢复闭环和三方合并建议。延续文件存储，增加不可变历史快照及旧备份读取；恢复只替换可编辑内容，不回退发布关联或地址。浏览器暂存按项目/草稿/窗口分区，仍以本机成功保存为准。导入 v1 备份生成独立草稿，单图上限 10 MiB、JSON 上限 64 MiB；先校验再公开草稿目录。

复用 node-diff3 3.2.1（MIT），只建议合并，确认保存仍检查最新版本。预览 URL 带构建编号，隔离目录内设置 Jekyll baseurl 并使用已有 Nokogiri 修正根路径和重复前缀；旧无版本绑定的预览需要重新生成，原文件仍保留。保留单构建任务限制，不引入自动清理、远端草稿同步、独立文章发布或自动推送。

## ADR-002 · 参考视觉语言，不复制展示对象和固定一屏交互

采用纸色/绿调/三栏/衬线/编号等视觉原则；用本地 SVG 概念图替代鸟类 WebGL。博客的首要任务是发现内容和阅读，使用自然滚动。减少外部依赖并保留无 JS 阅读能力。

## ADR-003 · 内容真实性优先

首页使用用户已提供的工作方向与公开 GitHub 身份。保留现有头像。正式文章、项目、成果和未提供的个人信息不填充，设计空态承担起步阶段的展示。

## ADR-004 · 搜索渐进实现

当前内容量为零，首页采用预渲染条目上的轻量匹配，覆盖标题/摘要/分类/标签。保留内页主题搜索。暂不引入向量数据库、付费搜索或 AI 问答；内容增长后根据数据量与检索质量决定。

## ADR-007 · 发布资源版本与友链肖像边界

2026-10-26 线上验收发现新友链 HTML 搭配旧缓存的 Atlas CSS，造成肖像铺满正文。GitHub Pages 的更新配置响应使用 `max-age=600`；主题 Worker 默认导入固定路径配置，使新版本提示也可能延迟。修复采用：Atlas CSS/JS URL 加构建时间版本；在 `assets/js/dist/sw.min.js` 覆盖主题 Worker，保持 Chirpy 7.1.1 的缓存/更新行为，只为其配置导入增加同一构建版本。保留原主题的“更新”确认，不强制关闭 PWA。主题升级时需同步比较这个覆盖文件。机制参考 [MDN updateViaCache](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerRegistration/updateViaCache)。

肖像容器与图片设置局部最大宽度，避免样式未就绪时撑满正文。友链按用户新参考调整为左侧照片与身份、右侧完整介绍；手机为紧凑的照片/姓名抬头加正文。

连续发布复核又发现安装新 Worker 时的 `cache.addAll` 可能从 HTTP 缓存取到上一版 HTML。因此安装预缓存使用 `Request(..., { cache: 'reload' })`，确保新版本缓存从网络刷新页面；其余离线命中、激活清理和手动更新行为保持原主题语义。

## ADR-008 · 复用编辑器组件实现本地写作和精确发布

2026-10-26 用户要求在本机实现编辑保存、真实主题预览、发布和部署跟踪。选用 EasyMDE 2.21.0、DOMPurify 3.4.17、yaml 2.9.1，本机 Node.js 24.22.1 使用项目专用目录和锁文件，不更换博客主题或文章格式。编辑器和预览分别绑定本机 4010/4011 端口；草稿、配图、恢复副本和操作记录保存在忽略目录 `.local/studio/`。

Front Matter CMS 有现成的 VS Code 内容管理和 Git 集成；Decap 可本地编辑，但其 git 模式会提交仓库全部变化，fs 模式只改文件。本项目需要独立中文界面、确认文章范围和 Pages 状态，因此复用编辑器组件，单独实现小范围发布协调，保留 `sync.cmd` 的原有全项目用途。参考：[EasyMDE](https://github.com/Ionaru/easy-markdown-editor)、[Front Matter Git 集成](https://frontmatter.codes/docs/git-integration/)、[Decap 本地代理](https://decapcms.org/docs/decap-proxy/)。

首版发布要求干净 main 且与远端一致。检查和确认分开，发布使用不可变文章快照，只提交文章与所引用配图；提交后再比较父提交及文件对象，防止其他程序在检查期间写入未核对内容。正常推送指定提交，失败重试不重复创建提交、不强推。根据提交编号匹配 Pages 工作流，并核对公开页 `studio-revision` 和配图哈希后才显示已上线。

本地预览复制允许的博客源目录，使用现有 Ruby 容器构建；PWA 关闭，服务来源与编辑接口分离。API 限制 Host/Origin/会话标记和路径，Git 凭据只由本机已有 Credential Manager 管理。发布功能在本地测试远端回归；本轮不向正式 GitHub 上传测试文章。
