# 决策记录

## ADR-001 · 保留 Jekyll + Chirpy 7.1.1

日期：2026-10-26。状态：采用。

| 方案 | 优点 | 代价 | 判断 |
| --- | --- | --- | --- |
| 小范围覆盖现有主题 | 保留 Markdown、链接、发布、阅读能力，维护成本低 | 主题升级时要核对覆盖接口 | 本轮采用 |
| 更换 Jekyll 主题 | 可获得新模板 | 视觉仍需定制，插件/页面需迁移 | 当前收益有限 |
| 迁移 Astro/Next 等 | 内容模型与交互自由度高 | 新构建链、部署与维护责任 | 当前无对应需求 |

## ADR-002 · 参考视觉语言，不复制展示对象和固定一屏交互

采用纸色/绿调/三栏/衬线/编号等视觉原则；用本地 SVG 概念图替代鸟类 WebGL。博客的首要任务是发现内容和阅读，使用自然滚动。减少外部依赖并保留无 JS 阅读能力。

## ADR-003 · 内容真实性优先

首页使用用户已提供的工作方向与公开 GitHub 身份。保留现有头像。正式文章、项目、成果和未提供的个人信息不填充，设计空态承担起步阶段的展示。

## ADR-004 · 搜索渐进实现

当前内容量为零，首页采用预渲染条目上的轻量匹配，覆盖标题/摘要/分类/标签。保留内页主题搜索。暂不引入向量数据库、付费搜索或 AI 问答；内容增长后根据数据量与检索质量决定。

## ADR-005 · 本地交付与手动发布

编辑和验证不触发推送。延续现有 Compose 和 `sync.cmd`；本轮不改 CI 权限、主题版本、原文章 URL、外部评论配置。生产发布与缓存验收必须另行记录。

## ADR-006 · 独立友链页与结构化资料

日期：2026-10-26。状态：采用。

使用 `_tabs/friends.html` 与 `_data/friends.yml`，路径固定为 `/friends/`。借鉴参考页的介绍结构，沿用 Atlas 样式与 Chirpy 内页，不引入新主题或远程头像请求。用户只提供一位共创者，因此仅展示这一条真实记录。2026-10-26 用户追加提供完整介绍及照片，照片存入 `assets/img/friends/` 并按原比例展示；无照片时回退到字母标识。新增人物时维护 YAML，先核对公开信息与链接。

## ADR-007 · 发布资源版本与友链肖像边界

2026-10-26 线上验收发现新友链 HTML 搭配旧缓存的 Atlas CSS，造成肖像铺满正文。GitHub Pages 的更新配置响应使用 `max-age=600`；主题 Worker 默认导入固定路径配置，使新版本提示也可能延迟。修复采用：Atlas CSS/JS URL 加构建时间版本；在 `assets/js/dist/sw.min.js` 覆盖主题 Worker，保持 Chirpy 7.1.1 的缓存/更新行为，只为其配置导入增加同一构建版本。保留原主题的“更新”确认，不强制关闭 PWA。主题升级时需同步比较这个覆盖文件。机制参考 [MDN updateViaCache](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerRegistration/updateViaCache)。

肖像容器与图片设置局部最大宽度，避免样式未就绪时撑满正文。友链按用户新参考调整为左侧照片与身份、右侧完整介绍；手机为紧凑的照片/姓名抬头加正文。

连续发布复核又发现安装新 Worker 时的 `cache.addAll` 可能从 HTTP 缓存取到上一版 HTML。因此安装预缓存使用 `Request(..., { cache: 'reload' })`，确保新版本缓存从网络刷新页面；其余离线命中、激活清理和手动更新行为保持原主题语义。
